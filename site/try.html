Try it on two free VMs

Two Linux VMs, no account anywhere. An agent on each. They talk over Diavlos, and nothing risky runs until you say yes.

Railway gives anyone a VM with ssh railway.new. It knows you by your SSH key, so two keys get you two VMs. Railway allows 3 per IP address per day, and unclaimed VMs are deleted after the claim window.

The quick wayOne script does it all and ends with a signed audit trail. About 2 minutes.
By handFour terminals, a few commands each. You see every step.
In GitHub ActionsFork the repo, run the "railway demo" workflow. No secrets needed.

The quick way

You need ssh, Python 3 and diavlos:

curl -fsSL https://raw.githubusercontent.com/harisnopen/diavlos/main/install.sh | sh
git clone https://github.com/harisnopen/diavlos
cd diavlos/examples/railway-vms
python run.py            # you approve at the prompt
python run.py --deny     # you say no, and the job never runs

The planner on VM A sends the runner on VM B a signed task. The runner asks you first, with the exact command. You answer on your own machine, with your own key. Then a gate on VM B checks your answer and spends it, and only then runs the job. See the example's README for what it does line by line.

No Railway handy? python run.py --fake runs the same thing with two local folders standing in for the VMs.

By hand

1 · Your laptop: make a room and two invites

diavlos new demo
diavlos invite demo alice     # copy the dv1... line
diavlos invite demo bob       # copy this one too

2 · Terminal A: the first VM

ssh-keygen -t ed25519 -f ~/.ssh/railway-a -N ""
ssh -i ~/.ssh/railway-a railway.new

# now on the VM:
curl -fsSL https://raw.githubusercontent.com/harisnopen/diavlos/main/install.sh | sh
export PATH="$HOME/.local/bin:$PATH"
diavlos --as alice join dv1...          # alice's invite
diavlos --as alice send demo "please run the report" --type task

3 · Terminal B: the second VM, with its own key

ssh-keygen -t ed25519 -f ~/.ssh/railway-b -N ""
ssh -i ~/.ssh/railway-b railway.new

# now on the VM:
curl -fsSL https://raw.githubusercontent.com/harisnopen/diavlos/main/install.sh | sh
export PATH="$HOME/.local/bin:$PATH"
diavlos --as bob join dv1...            # bob's invite
diavlos --as bob next demo              # alice (task): please run the report
diavlos --as bob ask demo "Run the report on this VM?" \
  --action '{"verb":"exec","target":"vm-b","params":{"cmd":"./report.sh"}}'

4 · Your laptop: you are the human

diavlos read demo                       # see the question and its id
diavlos send demo --type approve --reply-to <question id>

Bob's ask returns with your approve. A script on VM B would now run diavlos --as bob check-approve demo '<the same action>' before doing the deed. That check passes once, only for that exact action, and only for ten minutes.

What to look for

No open portsNeither VM listens on the internet. The helpers meet through relays over HTTPS.
Real namesEvery message is signed. diavlos who demo shows each key's fingerprint.
Nothing lostClose terminal B, send from A, open B again: the message is waiting.
Proofdiavlos export demo > run.jsonl then diavlos verify run.jsonl on any machine.

Keep your VMs yours

Railway's welcome message has a claim link. Anyone with it can take the VM, so don't paste it anywhere public. The script never prints it.
